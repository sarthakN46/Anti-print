# 🚀 Complete AWS Free Tier Deployment Guide for XeroxSaaS (Anti-Print)

This guide walks you through deploying the entire **XeroxSaaS** application on AWS completely within the **AWS Free Tier** limits, so you do not incur any hosting charges.

## 🌟 AWS Free Tier Services Used
1.  **Backend & Redis:** AWS EC2 `t2.micro` (or `t3.micro` depending on region) - **750 hours/month FREE** for the first 12 months.
2.  **Storage:** AWS S3 - **5 GB Storage & 20,000 GET / 2,000 PUT requests FREE** for the first 12 months.
3.  **Frontend:** AWS Amplify (or Vercel) - **100 build minutes/month, 5 GB storage, 15 GB/month transfer FREE** on AWS Amplify.
4.  **Database:** MongoDB Atlas M0 Sandbox - **100% Free Forever** (hosted on AWS nodes, avoiding AWS DocumentDB charges).

---

## 🔒 Step 0: AWS Account Safeguards (Do This First!)
To ensure you never get billed, set up a **Billing Alarm**:
1.  Log in to the [AWS Management Console](https://aws.amazon.com/).
2.  Search for **Billing** -> **Billing Preferences**.
3.  Check **Receive Free Tier Usage Alerts** to get email alerts when you approach 80% of free limits.
4.  Search for **CloudWatch** -> **Alarms** -> **Create Alarm** -> Select Metric **Estimated Charges** -> set trigger if estimated charges exceed `$0.01` to notify you immediately.

## 📁 Step 1: File Storage Setup (AWS S3)
The backend requires S3-compatible object storage to persist document uploads.
1.  Open the AWS Console, search for **S3**, and click **Create bucket**.
2.  **Bucket name:** Enter a unique name (e.g., `antiprint-original-storage`).
3.  **Region:** Choose the region closest to you (e.g., `us-east-1`).
4.  **Object Ownership:** Keep **ACLs disabled (recommended)**.
5.  **Block Public Access settings:** Keep **Block all public access** checked (highly secure; we access files using pre-signed secure URLs generated by the backend).
6.  Click **Create bucket**.
7.  Now search for **IAM** (Identity and Access Management) in the top bar.
8.  Go to **Users** -> **Create user**.
    *   **User name:** `antiprint-s3-user`
    *   Click **Next**.
9.  Select **Attach policies directly**.
10. Search for and select `AmazonS3FullAccess`. Click **Next** -> **Create user**.
11. Click on the newly created user `antiprint-s3-user` -> Go to the **Security credentials** tab.
12. Scroll down to **Access keys** and click **Create access key**.
13. Select **Application running outside AWS** (or Other) -> click **Next** -> **Create access key**.
14. **Copy the Access Key ID and Secret Access Key.** Save these credentials securely; you will need them for the backend configuration.

## 🗄️ Step 2: Database Setup (MongoDB Atlas on AWS)
*Do not use AWS DocumentDB as it has no permanent free tier. MongoDB Atlas M0 is free forever.*
1.  Sign up or login at [MongoDB Atlas](https://www.mongodb.com/cloud/atlas).
2.  Create a project, click **Create**, and choose **M0 (Free Tier)**.
3.  Select **AWS** as the provider and choose the same region you used for S3.
4.  Create a Database Username and Password. **Save the password**.
5.  Under **Network Access / IP Access List**, click **Add IP Address** and choose **Allow Access From Anywhere** (`0.0.0.0/0`). (This is required because EC2 free tier instances don't have static IPs unless configured with an Elastic IP).
6.  Go to **Database** -> **Connect** -> **Drivers**.
7.  Copy the connection string (e.g. `mongodb+srv://user:<password>@cluster0.abc.mongodb.net/?retryWrites=true&w=majority`). Replace `<password>` with your database password.

## 🖥️ Step 3: Backend Deployment (AWS EC2)
We will launch an EC2 instance, install Docker, and spin up the backend API and Redis cache using Docker Compose.

### A. Launch the EC2 Instance
1.  Go to the AWS Console -> search for **EC2**.
2.  Click **Launch instance**.
3.  **Name:** `antiprint-backend-server`
4.  **Application and OS Image:** Choose **Amazon Linux 2023** (Free tier eligible) or **Ubuntu 24.04 LTS**.
5.  **Instance type:** Choose `t2.micro` (or `t3.micro` if you are in a region where it is free tier eligible).
6.  **Key pair:** Click **Create new key pair**.
    *   Key pair name: `antiprint-key`
    *   Private key file format: `.pem` (for SSH)
    *   Click **Create key pair** and download the file. **Keep this file safe!**
7.  **Network settings:**
    *   Check **Allow SSH traffic from** -> Select **My IP** (safest) or **Anywhere** if you move around.
    *   Check **Allow HTTP traffic from the internet**.
    *   Check **Allow HTTPS traffic from the internet**.
8.  Click **Launch instance**.

### B. Configure Security Groups (Open Backend Ports)
The backend container runs on port `5000`. We need to open port `5000` to the public.
1.  In the EC2 Dashboard, click on your running instance.
2.  Select the **Security** tab at the bottom -> click your **Security Group** ID link.
3.  Click **Edit inbound rules**.
4.  Click **Add rule**:
    *   **Type:** `Custom TCP`
    *   **Port range:** `5000`
    *   **Source:** `Anywhere-IPv4` (`0.0.0.0/0`)
    *   **Description:** `Backend Express API`
5.  Click **Save rules**.

### C. Connect & Run the Deployment Script
1.  Open your terminal/command prompt and navigate to the directory where you downloaded the `antiprint-key.pem` key.
2.  Set key permissions (Mac/Linux only): `chmod 400 antiprint-key.pem`.
3.  SSH into your instance (replace `YOUR_EC2_PUBLIC_IP` with the IP shown in your EC2 console):
    *   *If using Amazon Linux:* `ssh -i antiprint-key.pem ec2-user@YOUR_EC2_PUBLIC_IP`
    *   *If using Ubuntu:* `ssh -i antiprint-key.pem ubuntu@YOUR_EC2_PUBLIC_IP`
4.  Create the backend environment file:
    ```bash
    mkdir -p ~/XeroxSaaS && cd ~/XeroxSaaS
    nano .env
    ```
5.  Copy and paste the following configuration, replacing placeholders with your actual details:
    ```env
    NODE_ENV=production
    PORT=5000
    MONGO_URI=your_mongodb_atlas_connection_string
    JWT_SECRET=your_random_generated_jwt_secret_string
    CLIENT_URL=http://your-frontend-domain.amplifyapp.com
    MINIO_ENDPOINT=s3.amazonaws.com
    MINIO_BUCKET_NAME=your_s3_bucket_name
    MINIO_ACCESS_KEY=your_iam_user_access_key
    MINIO_SECRET_KEY=your_iam_user_secret_key
    S3_FORCE_PATH_STYLE=false
    AWS_REGION=us-east-1
    ```
    *(Press `Ctrl+O` then `Enter` to save, and `Ctrl+X` to exit).*
6.  Run the automated deployment script already bundled in the repository:
    ```bash
    # Get the setup script
    curl -o deploy-aws.sh https://raw.githubusercontent.com/sarthakN46/Anti-print/deployment-ready/deploy-aws.sh
    chmod +x deploy-aws.sh
    # Run script to install Docker, Compose, pull code, and start containers
    ./deploy-aws.sh
    ```
7.  Verify the backend is running: `docker ps`. You should see `xerox-backend` and `redis` containers running.

## 🎨 Step 4: Frontend Deployment (AWS Amplify)
Amplify is the most optimized serverless host on AWS for modern static sites (Vite/React).
1.  Go to the AWS Console and search for **AWS Amplify**.
2.  Click **New App** -> **Host web app**.
3.  Select **GitHub** -> click **Continue** -> Authorize AWS to access your repositories.
4.  Select your repository `Anti-print` and the branch `deployment-ready`.
5.  **App settings:**
    *   Amplify will detect a monorepo.
    *   Check **Connecting a monorepo?** and enter `frontend` as the root directory.
6.  **Build settings:**
    *   Ensure the framework is identified as Vite/React.
7.  **Environment Variables:** Add your API endpoint:
    *   **Key:** `VITE_API_URL`
    *   **Value:** `http://YOUR_EC2_PUBLIC_IP:5000` (Make sure it starts with `http://` and ends with `:5000` without a trailing slash).
8.  Click **Save and Deploy**.
9.  Once the build finishes, Amplify will give you a live URL (e.g., `https://main.d1234abcde.amplifyapp.com`).

---

## 🔗 Step 5: Update CORS on Backend
To allow the frontend to safely communicate with your EC2 API:
1.  Go back to your EC2 SSH connection.
2.  Open your `.env` file: `nano ~/XeroxSaaS/.env`.
3.  Update `CLIENT_URL` to match your AWS Amplify URL:
    `CLIENT_URL=https://main.d1234abcde.amplifyapp.com` (no trailing slash).
4.  Re-run the docker containers to pick up the change:
    ```bash
    cd ~/XeroxSaaS
    docker-compose down
    docker-compose up -d
    ```

You are now fully set up on AWS, running 100% free of charge! 🚀
